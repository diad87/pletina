## Diferencias y límites que siguen abiertos

### Spotify por URL: limitación histórica superada

Se probó la playlist pública `37i9dQZF1DXcBWIGoYBM5M`, sin sesión de Spotify, token del usuario, backend ni proxy. La lectura directa del embed y de su variante oEmbed falló con `TypeError` en el navegador. oEmbed respondió HTTP 200, pero solo devolvió metadatos y un iframe, sin canciones. La API de elementos respondió HTTP 401 sin token. JSONP no ejecutó el callback; la API oficial de iframe permitió controles, sin exponer un listado de pistas, y el documento del iframe no fue legible desde el origen de la app.

Es una limitación **observada en esas rutas y esa ejecución**. La [evidencia conserva cada intento](../artifacts/pwa-port/imports-browser.json). La ruta nueva `embed/api/token` y la consulta paginada `queryPlaylist` sí funcionan directamente desde el navegador: [502 entradas completas en tres motores](../artifacts/spotify-import-investigation/guest-playlist-pagination-browser.json), sin servidor ni inicio de sesión. El token no es una credencial del usuario y no se persiste. Los fallos, páginas inconsistentes y límites se muestran sin guardar datos parciales. El botón Guardar sigue siendo necesario después de revisar coincidencias. CSV continúa como alternativa para privadas o fallos de Spotify; falta repetir el recorrido en una PWA instalada físicamente.

### Podcasts y proveedores

El port dispone de lectura directa RSS, catálogo público y respaldo de metadatos de episodios cuando el RSS no es legible. Algunos feeds probados aceptaron CORS y otros no; el respaldo puede tener menos episodios o idioma desconocido. La base web usa un espacio de IDs estable para programas y episodios, separado de canciones y vídeos añadidos. El progreso y las referencias de favoritos/playlists sobreviven a una actualización del feed. Los enclosures RSS publicados forman parte de los metadatos persistidos; las URLs temporales de audio resueltas de YouTube no se guardan como metadatos.

## Funciones que no son una carencia de la APK móvil

La importación de carpetas y los comandos de abrir/cambiar/revelar carpetas pertenecen a la versión de escritorio; la APK móvil de referencia no expone importación de carpetas locales. La PWA los oculta o los rechaza de forma explícita. La vista de Descargas web ya evita llamar a esas operaciones nativas incluso en una ventana ancha. La [configuración de capacidades](../src/lib/layout.svelte.ts) y [acciones de canciones](../src/lib/actions.ts) distinguen estos casos.

Android Auto y Apple CarPlay **no están implementados en esta distribución PWA**; sus integraciones nativas requieren trabajo separado. La actualización web se hace con el worker y el aviso de nueva versión, en lugar de descargar un APK mediante Obtainium. No se ofrece migración automática ni sincronización de la base nativa: la biblioteca web pertenece a su origen y perfil de navegador.

Las llamadas web no implementadas terminan con un error explícito en [invoke](../web-port/invoke.ts). El resultado vacío de biblioteca local y `newer_version: null` son adaptaciones del entorno web, no una implementación del escaneo de carpetas o del actualizador APK.
