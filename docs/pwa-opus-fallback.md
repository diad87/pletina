# Recuperación de audio del mismo vídeo con Opus

Compilación `c8ed230fbf100850`, fuente `5acf1a58af2e12555059c35f72b64ae240d9dc0c`. La PWA incorpora una parte portable del motor nativo: probar audio WebM/Opus del mismo vídeo cuando no funciona el AAC. Todo se ejecuta directamente en el navegador, sin servidor intermedio, cuentas ni suscripciones. No añade un reproductor de vídeo.

AAC conserva la prioridad. Opus sólo entra si `canPlayType('audio/webm; codecs="opus"')` devuelve `maybe` o `probably`; una excepción, ausencia o respuesta desconocida mantiene el comportamiento AAC anterior. Se rechazan vídeo multiplexado, otros códecs, DRM, DRC y pistas dobladas o descriptivas. La identidad del vídeo debe ser exacta y la política de audio original considera todos los metadatos, incluidos los formatos rechazados.

Las sondas comparten los ocho segundos existentes, con un máximo total de cuatro formatos. Un Opus disponible espera el resultado del AAC preferido; un AAC sano no se desplaza por comparar bitrates de códecs distintos. Si los cuatro puestos ya los ocupan AAC elegibles, Opus no amplía ese límite. La reproducción usa el mismo Audio, cola y controles. Cancelar retira todas las sondas y evita guardar un resultado tardío. No se amplía el plazo global de 45 segundos ni se habilitan descargas P1: comprobar metadatos de un stream no demuestra acceso legible al archivo completo.

También se aceptan versiones públicas del cliente P1 con sufijos mediante un token acotado de 1–64 caracteres ASCII `[A-Za-z0-9._+-]`. Se mantienen la validación del contexto anónimo y el rechazo de credenciales; no se ha regenerado la receta publicada. Este ajuste evita un rechazo prematuro de futuras versiones públicas y no se atribuye como causa del HTTP403.
